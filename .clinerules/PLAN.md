# MVP Implementation Plan: Foundational Workout Engine

**Objective:** Create a standalone Flutter app that allows a user to select, execute, and save the results of the "Foundational Ball Control & Finishing" workout. All data will be stored locally on the device.

---

## Epic 1: Data Models & Local Content Loading

**Goal:** Define the data structures and load the workout blueprint from a local asset.

- [x] **T1.1: Create Data Models**
  - **Description:** Create the Dart data models for `WorkoutBlueprint` and `Drill` that can be automatically serialized/deserialized from JSON using the `json_serializable` package.
  - **Inputs:** The `workoutBlueprint` JSON structure.
  - **Outputs:** `lib/models/workout_blueprint.dart` and `lib/models/drill.dart` files with necessary classes and annotations. `workout_blueprint.g.dart` and `drill.g.dart` files generated by `build_runner`.
  - **Validation:** A unit test (`test/model_test.dart`) that successfully creates a `WorkoutBlueprint` object from a JSON string and asserts its properties are correct.

- [x] **T1.2: Create Local Workout Asset**
  - **Description:** Create a local JSON asset file containing the "Foundational Ball Control & Finishing" workout blueprint.
  - **Inputs:** The `workoutBlueprint` JSON data.
  - **Outputs:** An `assets/workouts.json` file. The `pubspec.yaml` file is updated to include the `assets/` directory.
  - **Validation:** Manually verify that the `assets/workouts.json` file exists and `pubspec.yaml` is correctly configured.

- [x] **T1.3: Implement Workout Repository**
  - **Description:** Implement a `WorkoutRepository` class that can read and parse the `workouts.json` file from the assets.
  - **Inputs:** The `assets/workouts.json` file.
  - **Outputs:** A `lib/repositories/workout_repository.dart` file containing a class with a `getWorkoutBlueprint()` method.
  - **Validation:** A unit test (`test/repository_test.dart`) that calls `getWorkoutBlueprint()` and asserts that a valid `WorkoutBlueprint` object is returned.

---

## Epic 2: UI - Workout Selection & Detail Screens

**Goal:** Build the user interface for Browse and selecting the workout, based on the provided mockups.

- [x] **T2.1: Build Workout Library Screen**
  - **Description:** Build the initial screen of the app. It should use a `FutureBuilder` to fetch data from the `WorkoutRepository` and display a card for the workout.
  - **Inputs:** `WorkoutRepository` class.
  - **Outputs:** A `lib/screens/library/workout_library_screen.dart` widget. The `main.dart` file is updated to show this screen as the `home`.
  - **Validation:** A widget test (`test/screens/library_screen_test.dart`) that pumps the screen, waits for the future to resolve, and verifies the workout name and objective text are displayed.

- [x] **T2.2: Implement Navigation to Detail Screen**
  - **Description:** Implement the logic to navigate from the `WorkoutLibraryScreen` to the `WorkoutDetailScreen` when the user taps on the workout card.
  - **Inputs:** `WorkoutLibraryScreen` widget.
  - **Outputs:** `onTap` functionality on the workout card that pushes a new route using `Navigator.push()`.
  - **Validation:** A widget test that simulates a tap on the card and verifies that the `WorkoutDetailScreen` is pushed to the navigator stack.

- [x] **T2.3: Build Workout Detail Screen**
  - **Description:** Build the screen that shows the detailed list of drills for the selected workout, matching Mockup #1.
  - **Inputs:** A `WorkoutBlueprint` object passed as an argument.
  - **Outputs:** A `lib/screens/detail/workout_detail_screen.dart` widget.
  - **Validation:** A widget test that pumps the `WorkoutDetailScreen` with a mock `WorkoutBlueprint` and verifies that the name, objective, and a list of all drill names are displayed.

## Epic 3: Core Workout Engine

**Goal:** Create the active workout experience, managing state and displaying the correct UI for each drill type.

- [x] **T3.1: Create Workout State Service**
  - **Description:** Create a state management service using `Provider` (`ChangeNotifier`) to manage the state of an active workout session (e.g., current drill index, results).
  - **Inputs:** A `WorkoutBlueprint` object to start a session.
  - **Outputs:** A `lib/services/workout_state.dart` file.
  - **Validation:** A unit test that creates a `WorkoutState` instance, starts a workout, and asserts that the initial state (current drill, etc.) is correct.

- [x] **T3.2: Build Active Workout Screen**
  - **Description:** Build the main screen that listens to the `WorkoutState` and dynamically displays the correct UI for the current drill.
  - **Inputs:** `WorkoutState` service.
  - **Outputs:** A `lib/screens/active/active_workout_screen.dart` widget.
  - **Validation:** A widget test that provides a mock `WorkoutState` and verifies that changing the current drill `type` in the state correctly switches between showing a Timer UI vs. a Rep Counter UI.

- [x] **T3.3: Implement Timed Drill Logic**
  - **Description:** Implement the specific UI and timer logic for drills with `type: "TIMED"`.
  - **Inputs:** A `Drill` object of type `TIMED`.
  - **Outputs:** A widget that displays a countdown timer. When the timer finishes, it calls a method on `WorkoutState` to advance to the next drill.
  - **Validation:** A widget test that uses `tester.pump()` to advance time and verifies the timer text updates correctly and that `nextDrill()` is called on a mock `WorkoutState` upon completion.

- [x] **T3.4: Implement Rep-Based Drill Logic**
  - **Description:** Implement the UI for `REP_BASED` drills, including the "Log Set" Modal for data entry.
  - **Inputs:** A `Drill` object of type `REP_BASED`.
  - **Outputs:** A widget with a make/target counter and a "LOG SET" button that opens a modal. Saving the modal updates the `WorkoutState`.
  - **Validation:** A widget test that simulates tapping "LOG SET", verifies the modal appears, simulates data entry, and verifies that the correct logging method is called on a mock `WorkoutState`.

- [x] **T3.5: Implement Make Target Timed Drill Logic**
  - **Description:** Implement the UI for the `MAKE_TARGET_TIMED` drill type.
  - **Inputs:** A `Drill` object of type `MAKE_TARGET_TIMED`.
  - **Outputs:** A widget with an upward-counting timer and a make counter.
  - **Validation:** A widget test that simulates tapping `+1 MAKE`, verifies the counter updates, and asserts that the timer stops updating once the target makes are reached.

---

## Epic 4: Results Persistence & Summary

**Goal:** Save the completed workout session to a local file and display the results on a summary screen.

- [ ] **T4.1: Implement Storage Service**
  - **Description:** Create a `StorageService` to save and load workout session data to/from a local JSON file using `path_provider`.
  - **Inputs:** A completed `WorkoutSession` object.
  - **Outputs:** A `lib/services/storage_service.dart` file.
  - **Validation:** A unit test that mocks the file system, calls `saveSession()`, and verifies that a `writeAsString()` method is called with the correct data.

- [ ] **T4.2: Build Injury Log Screen**
  - **Description:** Build the screen (Mockup #6) that appears after the last drill, allowing the user to log their physical feeling.
  - **Inputs:** The active `WorkoutState`.
  - **Outputs:** A `lib/screens/active/injury_log_screen.dart` widget. The "FINISH & SAVE" button calls the `StorageService`.
  - **Validation:** A widget test that simulates selecting a feeling, entering text, and tapping "FINISH & SAVE", then verifies that the `saveSession` method on a mock `StorageService` is called.

- [ ] **T4.3: Build Workout Summary Screen**
  - **Description:** Build the screen (Mockup #7) that displays the results from a completed session.
  - **Inputs:** A `WorkoutSession` object.
  - **Outputs:** A `lib/screens/summary/workout_summary_screen.dart` widget.
  - **Validation:** A widget test that pumps the screen with a mock `WorkoutSession` object and verifies all key data points are displayed correctly.

- [ ] **T4.4: Build Workout History Screen**
  - **Description:** Build a screen that loads all saved sessions from the `StorageService` and displays them in a list.
  * **Inputs:** `StorageService` class.
  * **Outputs:** A `lib/screens/history/workout_history_screen.dart` widget.
  * **Validation:** A widget test that provides a mock `StorageService` returning a list of sessions, pumps the screen, and verifies the `ListView` is populated correctly.
